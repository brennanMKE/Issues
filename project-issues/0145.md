## Description

Running the `Issues (Beta)` scheme from Xcode fails with:

```
Could not launch "Issues" (IDELaunchErrorDomain code 20)
The file "Issues.app" couldn't be opened because there is no such file.
  .../DerivedData/Issues-…/Build/Products/Debug/Issues.app  (NSCocoaErrorDomain 260)
```

The build **succeeds** — only the launch fails.

## Root cause

`Configuration/Beta.xcconfig` set `PRODUCT_NAME = Issues Beta`. The Beta scheme
selects that variant via a pre-action (`set-environment.sh Beta` → writes
`Configuration/Active.xcconfig`, which `App.xcconfig` includes). So the build
produces **`Issues Beta.app`**.

But Xcode resolves the launch/run path from build settings snapshotted at the
*start* of the run operation — before the pre-action rewrites `Active.xcconfig`
— combined with the scheme's hard-coded `BuildableName`. It therefore looks for
`Issues.app`, which the Beta build never emits.

General rule: **a pre-action-written xcconfig must never change `PRODUCT_NAME`**
(or anything else that determines `FULL_PRODUCT_NAME` / the launch path). Bundle
ID, Sparkle feed URLs, and display name are safe to swap that way; the product
name is not. The intent of #0137 was a separate *bundle ID* for beta, not a
separate product name — the `PRODUCT_NAME` override was scope creep on top of it.

## Fix (committed in 76b9d39 "fixes build")

- `Configuration/Beta.xcconfig`: removed `PRODUCT_NAME = Issues Beta`. Both
  variants now build `Issues.app`, differentiated only by bundle id
  (`co.sstools.Issues.beta`) and the blanked Sparkle feed.
- `Issues (Beta).xcscheme`: updated all four `BuildableName` entries from
  `Issues Beta.app` → `Issues.app` to match.

## Verification

- `set-environment.sh Beta` then
  `xcodebuild -scheme 'Issues (Beta)' -configuration Debug build` produces
  `Issues.app` with bundle id `co.sstools.Issues.beta`, CLI binaries still
  bundled under `Contents/SharedSupport/bin/`. ✓ (confirmed)
- Running the Beta scheme from Xcode launches without the LaunchServices error.

## Out of scope

- A visibly distinct beta name in Finder/Dock/menubar. If wanted, add
  `CFBundleDisplayName = $(PRODUCT_DISPLAY_NAME)` to `Info.plist` and set
  `PRODUCT_DISPLAY_NAME` per xcconfig — display name does not affect the `.app`
  filename or launch path, so it's safe.
- Distinct `.app` filenames for side-by-side beta/prod installs. That requires a
  real Xcode build *configuration* (resolved statically before launch), not the
  `Active.xcconfig`-swap trick.
