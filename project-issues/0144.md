## Description

When a new tab is created, the folder picker shows a "Recent" list of previously watched folder paths. That list has no upper bound — every folder ever opened keeps accumulating, so over time the view keeps getting taller without limit. It should show at most 10 entries, and they should be the most recently used ones.

## Steps to reproduce

1. Open and close several different folders over time (more than 10 distinct paths).
2. Create a new tab to bring up the folder picker.
3. Observe the "Recent" list.

## Expected behavior

The "Recent" list is capped at 10 (or fewer) entries, showing the most recently used folders.

## Actual behavior

Every remembered folder is listed. The list grows unbounded as more folders are opened, making the picker progressively taller.

## Notes

- `FolderPickerRememberedListView` renders `ForEach(bookmarks.remembered) { … }` with no cap — every entry is shown.
- `FolderBookmarkService.remembered` is already kept sorted by `lastUsed` descending (most recent first), so the most-recent ordering is in place; the fix is just to limit how many are displayed (e.g. `bookmarks.remembered.prefix(10)`).
- Decide whether to cap only the display (view-level `.prefix(10)`) or also prune the persisted list in `FolderBookmarkService` so old bookmarks don't linger in `UserDefaults`. View-level capping is the minimal fix; service-level pruning also bounds the stored blob.
- Relevant files: `IssuesKit/Sources/IssuesAppKit/Views/FolderPickerRememberedListView.swift`, `IssuesKit/Sources/IssuesCore/Services/FolderBookmarkService.swift`.

## Root cause

`FolderPickerRememberedListView` rendered `ForEach(bookmarks.remembered) { … }` with no cap, and `FolderBookmarkService` never trimmed its `remembered` array (or the persisted `UserDefaults` blob). Every distinct folder ever opened accumulated, so both the picker view and the stored JSON grew without bound.

## Fix

Bounded the list at both layers:

- Added `FolderBookmarkService.maxRemembered = 10` and a pure `static func pruned(_:)` helper that sorts by `lastUsed` descending and keeps at most `maxRemembered`.
- Applied `pruned(_:)` in `remember(url:)` (caps after inserting a new entry) and in `load()` (trims an already-oversized persisted blob on launch), so `UserDefaults` stays bounded.
- Capped the view with `bookmarks.remembered.prefix(FolderBookmarkService.maxRemembered)` as a defensive guard.

The list was already sorted most-recent-first, so trimming keeps the 10 most recently used folders and drops the stalest.

## Gotchas

The service's `remember(url:)` path can't be unit-tested directly because it creates a real security-scoped bookmark (`url.bookmarkData(...)` with `.withSecurityScope`), which needs the sandbox entitlement and a live URL. The cap logic was factored into the pure `pruned(_:)` helper specifically so it can be tested with synthetic `RememberedFolder` values.
