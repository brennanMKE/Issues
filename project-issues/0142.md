## Description

Issue selection and the detail panel have the worst regression history of any single feature in the app — #0040 (list view selection unreliable), #0041 (detail panel body not updating on selection change), #0042 (double-click broken after the #0040 fix). Three separate bugs in one flow, all caught by eye. This suite locks in the selection semantics so the next change to `selectedIssueID`, `DetailPanelView`, or List-view tap handling trips a test instead of shipping.

## Regressions this suite would have caught

- **#0040** — List view row selection was unreliable; the detail panel rarely appeared on tap. A test tapping `issue-cell.0001` and asserting `detail-panel.root` appears within 1 second would have failed immediately.
- **#0041** — Detail panel body didn't update when the selected issue changed. A test selecting 0001, then selecting 0002, and asserting `detail-panel.title` changed would have caught it on the first run after the regression.
- **#0042** — List view lost double-click-to-open after the #0040 fix. A test double-tapping a cell and asserting the markdown sheet appeared would have failed the moment the gesture was broken.
- **#0072** — Detail panel markdown re-rendered on every resize frame, causing visible jitter. While the *cause* was a layout cycle, a test asserting `detail-panel.description` exists and is stable (no repeated `waitForExistence` flapping) would have surfaced the instability.

## Test cases

All tests use the foundation from #0139. Most run in List view (most deterministic layout); where noted they also run in Swimlane to confirm cross-mode consistency.

### Basic selection — would catch #0040

- **Tapping `issue-cell.0001` opens the detail panel.** Tap `issue-cell.0001`. Assert `detail-panel.root` appears within 1 second. Assert `detail-panel.title` contains the expected title text.
- **Detail panel shows the correct status.** Assert `detail-panel.status` accessibilityValue equals `"open"` (fixture 0001's status).
- **Detail panel shows description text.** Assert `detail-panel.description` is non-empty.

### Selection change — would catch #0041

- **Tapping a second issue updates the detail panel.** Tap `issue-cell.0001`. Assert `detail-panel.title` reflects 0001. Tap `issue-cell.0002`. Assert `detail-panel.title` changes to 0002's title within 1 second. Assert 0001's title is no longer shown.
- **Selecting the same issue again does not collapse the panel.** Tap `issue-cell.0001`. Tap it again. Assert `detail-panel.root` still exists.

### Deselection / panel collapse

- **Pressing Escape (or clicking outside) deselects the issue.** If the app supports keyboard deselection, press Escape. Assert `detail-panel.root` disappears. (If deselection is not currently implemented, document as `XCTSkip` until it is.)
- **Applying a filter that hides the selected issue collapses the panel.** Select `issue-cell.0002` (in-progress/Services). Apply `filter.status.open`. Assert `issue-cell.0002` is absent. Assert `detail-panel.root` is absent (selection was cleared because the selected issue is no longer visible).

### Keyboard navigation

- **Arrow keys move selection through the issue list.** Select `issue-cell.0001`. Press the down-arrow key. Assert `detail-panel.title` changes to the next issue in the list order. Press up-arrow. Assert it returns to 0001.
- **Enter opens the markdown preview sheet.** Select an issue. Press Enter. Assert `markdown-sheet.root` (or equivalent sheet element) appears. (If the keyboard shortcut is Spacebar per #0044, test that instead.)

### Markdown sheet (Quick Look–style preview — #0044)

- **Spacebar opens the markdown sheet for the selected issue.** Select `issue-cell.0001`. Press Space. Assert a sheet appears containing the issue's title text.
- **Spacebar again dismisses the sheet (#0045).** Press Space. Assert the sheet is dismissed.
- **Closing the sheet does not clear selection.** After dismissing, assert `detail-panel.root` is still present.

### Cross-view-mode consistency

- **Selection works the same in Swimlane, Timeline, and Recent views.** Switch to each mode in turn. Tap `issue-cell.0001`. Assert `detail-panel.root` appears and shows 0001's title.

## Accessibility identifiers needed (from #0139)

- `issue-cell.<id>` — covered.
- `detail-panel.root` — covered.
- `detail-panel.title` — covered.
- `detail-panel.status` — covered.
- `detail-panel.description` — covered.
- `markdown-sheet.root` — **new**, not in #0139 inventory. Add to the markdown preview sheet's root view.

## Out of scope

- The full markdown rendering fidelity inside the detail panel or preview sheet (snapshot territory; #0018 and #0048 track rendering issues separately).
- Cross-reference link navigation inside the markdown body (#0054).
- Attachment thumbnails in the detail panel (#0056).
- Double-click-to-open behavior (#0042/#0043 resolved this as "rely on Enter/Space"; that resolution is what the keyboard tests above verify).

## Acceptance criteria

- All test cases pass under `xcodebuild -scheme 'Issues (Beta)' -destination 'platform=macOS' test`.
- The #0040 regression test (`testTappingIssueCellOpensDetailPanel`) is marked with a comment naming the issue.
- The #0041 regression test (`testSelectionChangeCausesDetailPanelToUpdate`) is similarly marked.
- The filter-hides-selection test verifies *both* that the cell is gone *and* that the panel is gone (two independent assertions, not one chained check).

## Notes

- Depends on #0139.
- List view is the most regression-prone layout for tap handling because cells are laid out by `List` (UIKit-backed on macOS, extra indirection). Prefer List view for the basic tap tests; the cross-mode consistency test confirms Swimlane and others work the same way.
- `detail-panel.description` is a rendered markdown surface. Its exact text content may vary if the markdown renderer changes; assert non-empty rather than exact string match unless you need to lock in specific rendering.
- The `filter.status.open` → selection-cleared test is the most complex setup in this suite. Run it last within the test method to keep failure messages readable.
