# 0137 — Separate Bundle ID for development vs release builds via xcconfig schemes

| | |
|---|---|
| **Status** | open |
| **Module** | Build / Config |
| **Platform** | macOS |
| **First seen** | 2026-05-24 |

## Description

Running the app from Xcode during development uses the same Bundle ID (`co.sstools.Issues`) as the production release. This means the dev build and the App Store / notarized DMG build share the same container, UserDefaults, Sparkle state, and dock presence. A separate Bundle ID for the development build (e.g. `co.sstools.Issues.beta`) would allow both to coexist cleanly on the same machine and prevent dev data from contaminating production state.

## Expected behavior

- **Xcode / development builds** use Bundle ID `co.sstools.Issues.beta`, product name `Issues Beta`, a visually distinct app icon, and a separate Sparkle feed URL (or none).
- **Release builds** (built via the Prod scheme or `release.sh`) use Bundle ID `co.sstools.Issues`, product name `Issues`, and the production Sparkle feed.
- Switching between the two requires no manual edits to any source file or xcconfig. The build scheme drives everything.

## Approach

Follow the pattern documented in the `xcode-betaprod` Claude Code skill:

1. **Add `Active.xcconfig`** to `Configuration/`. This file contains a single `#include` that points at either `Beta.xcconfig` or `Prod.xcconfig`. It is generated (or overwritten) by a pre-build script; add it to `.gitignore` so it never appears as a dirty working-tree change.

2. **Add `Beta.xcconfig` and `Prod.xcconfig`** to `Configuration/`. Each overrides the keys that differ between environments:

   | Key | Beta value | Prod value |
   |---|---|---|
   | `PRODUCT_BUNDLE_IDENTIFIER` | `co.sstools.Issues.beta` | `co.sstools.Issues` |
   | `PRODUCT_NAME` | `Issues Beta` | `Issues` |
   | `ASSETCATALOG_COMPILER_APPICON_NAME` | `AppIconBeta` | `AppIcon` |
   | `SU_FEED_URL` | *(omit or point at a beta feed)* | `$(HTTPS)/issues.sstools.co/appcast.xml` |

3. **Add `#include? "Active.xcconfig"` to `Configuration/App.xcconfig`** (optional include so cold builds without `Active.xcconfig` still compile). `App.xcconfig` is the target-level xcconfig — placing the include there ensures `Beta.xcconfig`/`Prod.xcconfig` can override `PRODUCT_BUNDLE_IDENTIFIER` cleanly over the project-level `Build.xcconfig`.

4. **Create `scripts/set-environment.sh`** — takes a single argument (`Beta` or `Prod`), writes `Active.xcconfig` with the appropriate `#include`, and optionally copies the matching app icon set into `Issues/Assets.xcassets/AppIcon.appiconset/`.

5. **Create two shared build schemes:**
   - `Issues (Beta)` — pre-action runs `set-environment.sh Beta`
   - `Issues (Prod)` — pre-action runs `set-environment.sh Prod`

   Both pre-actions must be configured to "Provide build settings from" the Issues target so `$PROJECT_DIR` is defined.

6. **Add an `AppIconBeta` icon set** to `Issues/Assets.xcassets/` — visually distinct from `AppIcon` (e.g. a tinted or badged variant) so it is immediately obvious which build is running.

7. **Update `.gitignore`** to exclude `Configuration/Active.xcconfig`.

## Implementation order

1. Confirm with user which keys belong in Beta vs Prod (Bundle ID, name, icon, Sparkle feed).
2. Implement `scripts/set-environment.sh` and the xcconfig files — no Xcode project changes yet.
3. Add schemes + pre-actions to `Issues.xcodeproj` (or instruct user to add them manually since the project file is complex to edit by hand).
4. Verify by running `./scripts/set-environment.sh Beta`, building, and confirming the Beta bundle ID appears in `codesign -dv`.

## Notes

- `Configuration/App.xcconfig` currently holds `PRODUCT_BUNDLE_IDENTIFIER`, `PRODUCT_NAME`, `ASSETCATALOG_COMPILER_APPICON_NAME`, and Sparkle keys. The Beta/Prod split will override only the keys that differ; everything else stays in `App.xcconfig`.
- `MARKETING_VERSION` and `CURRENT_PROJECT_VERSION` should stay in `App.xcconfig` (same version for both environments) unless a separate Beta versioning scheme is desired.
- The `xcode-betaprod` Claude Code skill can assist with the full setup.
- Running `xcodebuild -scheme "Issues (Beta)"` from the terminal does NOT execute pre-actions. Call `./scripts/set-environment.sh Beta` manually before headless builds.
- The `AppIconBeta` asset requires explicit user sign-off before implementation — the Beta bundle ID and name changes are sufficient to distinguish builds in the meantime.
