# 0138 — Use screenshot.sh to capture the running app during automated issue work

| | |
|---|---|
| **Status** | open |
| **Module** | Build / Config |
| **Platform** | macOS |
| **First seen** | 2026-05-24 |

## Description

`scripts/screenshot.sh` captures the Issues Beta window by bundle ID (`co.sstools.Issues.beta`) using the `windows` CLI and `screencapture -l`. Currently this script exists but is not wired into the issue-resolution workflow. Subagents verifying UI fixes have no standard way to produce visual evidence — they rely on build success alone. Integrating `screenshot.sh` into the automated workflow lets subagents attach before/after screenshots to resolved issues, turning the `## Verification` section from "it built" into actual observed output.

Depends on #0137 (Beta bundle ID via xcconfig schemes) — the script will fail silently if the beta build is not running.

## Expected behavior

- During issue resolution, a subagent can call `./scripts/screenshot.sh` after launching (or confirming the launch of) the Issues Beta app to capture the current window state.
- The captured PNG is copied into `project-issues/NNNN/` and referenced in the issue's `## Attachments` section with the correct relative path (`NNNN/screenshot.png`).
- The `## Verification` section of the resolved issue names the screenshot as evidence alongside the test command output.
- If the app is not running, the script exits with a warning and the subagent notes the gap in verification rather than silently skipping.

## Approach

1. **Document the workflow in `project-issues/Issues.md`** under a "Visual verification" heading: launch Issues Beta (`Issues (Beta)` scheme or `open -b co.sstools.Issues.beta`), run `./scripts/screenshot.sh`, copy the output file into `project-issues/NNNN/`, and embed it with `![caption](NNNN/screenshot.png)`.

2. **Update `scripts/screenshot.sh`** to accept an optional output path argument so callers can direct the capture straight to `project-issues/NNNN/` without a manual `mv`:

   ```sh
   ./scripts/screenshot.sh project-issues/0138/after.png
   ```

   When no argument is given, the existing `screenshots/screenshot_TIMESTAMP.png` behavior is preserved.

3. **Document the `windows` dependency** — `screenshot.sh` relies on a `windows` CLI tool (finds windows by bundle ID). Add a note in `Issues.md` or `scripts/screenshot.sh` header that this tool must be available (`which windows`) and where to install it if missing.

4. **Add a `screenshots/` entry to `.gitignore`** so timestamped captures from the default output path don't accumulate as untracked files.

## Notes

- `screencapture -l WINDOW_ID` captures the specific window without the desktop background, which is cleaner than a full-screen grab.
- The `windows` command resolves the window ID from the bundle ID — this is why #0137 (beta bundle ID) is a prerequisite: a dev build using `co.sstools.Issues` would conflict with the production install and the wrong window could be captured.
- Screenshots placed in `project-issues/NNNN/` for issue attachments should use descriptive names (`before.png`, `after.png`, `state.png`) rather than timestamped names.
- The `screenshots/` folder in the repo root is for ad-hoc captures during development; issue attachments go in `project-issues/NNNN/` only.
